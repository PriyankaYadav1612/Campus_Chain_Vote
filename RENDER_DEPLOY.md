# Deploying CampusChainVote on Render

This guide walks you through deploying the full stack (frontend, backend, database) on [Render](https://render.com), plus deploying the smart contract to Sepolia testnet.

---

## Architecture on Render

| Service | Render Type | Notes |
|---------|------------|-------|
| `campus-chain-vote-backend` | Web Service (Node.js) | Express API |
| `campus-chain-vote-frontend` | Static Site | React/Vite SPA |
| `campus-chain-vote-db` | PostgreSQL | Managed DB |
| Smart Contract | External (Sepolia) | Deploy once, set CONTRACT_ADDRESS env var |

> **Why no Hardhat node on Render?**  
> Hardhat's in-memory chain resets on every restart, wiping all elections and votes. Use Sepolia testnet instead — it's persistent and free.

---

## Prerequisites

1. A [Render account](https://dashboard.render.com/register) (free tier works)
2. An [Alchemy](https://alchemy.com) or [Infura](https://infura.io) account for a Sepolia RPC URL
3. A funded Sepolia wallet (get free ETH from [sepoliafaucet.com](https://sepoliafaucet.com))
4. Node.js 20+ installed locally for the one-time contract deployment

---

## Step 1 — Deploy the Smart Contract to Sepolia

This is a **one-time step** done from your local machine.

### 1a. Get a Sepolia RPC URL

- Sign up at [Alchemy](https://dashboard.alchemy.com) → Create App → Network: **Ethereum Sepolia**
- Copy the HTTPS endpoint, e.g.:  
  `https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY`

### 1b. Fund a wallet

- Use MetaMask to create/use a wallet
- Get testnet ETH from [https://sepoliafaucet.com](https://sepoliafaucet.com)
- Export the **private key** (MetaMask → Account Details → Export Private Key)

### 1c. Set local environment variables

Create or edit `.env` in the project root:

```env
SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY
SEPOLIA_PRIVATE_KEY=0xYOUR_WALLET_PRIVATE_KEY
RELAYER_PRIVATE_KEY=0xYOUR_WALLET_PRIVATE_KEY
RELAYER_ADDRESS=0xYOUR_WALLET_ADDRESS
```

### 1d. Deploy the contract

```bash
# From the project root
npx hardhat run scripts/deploy.js --network sepolia
```

This writes `data/deployment.json`. **Copy the `address` value** — you'll need it as `CONTRACT_ADDRESS`.

Example output:
```
CampusVoting deployed to: 0xAbCdEf1234567890...
```

## Step 2 — Deploy to Render via Blueprint (render.yaml)

The `render.yaml` in this repo defines all three services. Use Render Blueprints to deploy everything at once.

### 2a. Push this repo to GitHub/GitLab

```bash
git add render.yaml RENDER_DEPLOY.md backend/src/app.js
git commit -m "feat: add Render deployment configuration"
git push origin main
```

### 2b. Create a Blueprint on Render

1. Log in to [Render Dashboard](https://dashboard.render.com)
2. Click **New** → **Blueprint**
3. Connect your GitHub/GitLab account and select this repository
4. Render reads `render.yaml` and shows you the services to create
5. Click **Apply** — Render will:
   - Create the PostgreSQL database
   - Deploy the backend Web Service
   - Deploy the frontend Static Site

## Step 3 — Set Required Environment Variables

Some variables are marked `sync: false` in `render.yaml` and must be set manually.

### Backend environment variables

Go to **Render Dashboard** → `campus-chain-vote-backend` → **Environment**:

| Variable | Value | Notes |
|----------|-------|-------|
| `RPC_URL` | `https://eth-sepolia.g.alchemy.com/v2/YOUR_KEY` | Your Alchemy/Infura Sepolia URL |
| `RELAYER_PRIVATE_KEY` | `0xYOUR_PRIVATE_KEY` | Funded Sepolia wallet private key |
| `RELAYER_ADDRESS` | `0xYOUR_WALLET_ADDRESS` | Address matching the private key |
| `CONTRACT_ADDRESS` | `0xYOUR_DEPLOYED_CONTRACT` | From Step 1d |
| `FRONTEND_URL` | `https://campus-chain-vote-frontend.onrender.com` | Your actual frontend URL from Render |
| `SMTP_HOST` | `smtp.gmail.com` (or your provider) | Optional — for OTP emails |
| `SMTP_USER` | your email | Optional |
| `SMTP_PASS` | your email app password | Optional |

> `JWT_SECRET` and `NULLIFIER_SECRET` are auto-generated by Render (`generateValue: true`). **Do not change them after the first deploy** — changing JWT_SECRET logs everyone out; changing NULLIFIER_SECRET makes old nullifiers invalid (votes could be double-counted).

> `DATABASE_URL` is automatically injected from the managed PostgreSQL instance.

### Frontend environment variables

Go to **Render Dashboard** → `campus-chain-vote-frontend` → **Environment**:

| Variable | Value |
|----------|-------|
| `VITE_API_URL` | `https://campus-chain-vote-backend.onrender.com/api` |

> ⚠️ `VITE_API_URL` is baked into the JS bundle at build time by Vite. After setting it, **trigger a manual redeploy** of the frontend: Render Dashboard → frontend service → **Manual Deploy**.

## Step 4 — Verify Deployment

1. Open `https://campus-chain-vote-backend.onrender.com/api/health`  
   Expected: `{"status":"ok","timestamp":"...","service":"CampusChainVote Backend API"}`

2. Open `https://campus-chain-vote-frontend.onrender.com`  
   You should see the login page.

3. Register an admin and create an election to confirm the blockchain integration works.

---

## Step 5 — Seed Initial Data (Optional)

If you want to seed the database with students and elections from your CSV files:

```bash
# Set DATABASE_URL to your Render DB connection string (from Render Dashboard → DB → Connection)
# Then from the backend/ directory:
DATABASE_URL="postgresql://..." node prisma/seed.js
```

Or you can use the Admin Dashboard in the app to upload CSVs directly.

## Free Tier Limitations

| Limitation | Impact |
|-----------|--------|
| Web services spin down after 15 min of inactivity | First request after idle takes ~30s (cold start) |
| Free PostgreSQL expires after 90 days | Upgrade to Starter ($7/mo) before expiry |
| 512 MB RAM per service | Sufficient for this app |
| 0.1 CPU per service | Sufficient for this app |

To avoid cold starts, upgrade to a paid plan or use [UptimeRobot](https://uptimerobot.com) to ping `/api/health` every 10 minutes (free).

## Updating the Deployment

Every push to your connected branch triggers an automatic redeploy on Render.

For **schema changes**, update `backend/prisma/schema.prisma` and push — the build command (`prisma db push`) applies the changes automatically.

For **new contract deployments** (e.g. after changing `CampusVoting.sol`):
1. Redeploy to Sepolia: `npx hardhat run scripts/deploy.js --network sepolia`
2. Update `CONTRACT_ADDRESS` in the Render backend environment variables
3. Trigger a manual redeploy of the backend

## Environment Variable Reference

Full list of all backend environment variables:

```env
# Required
NODE_ENV=production
DATABASE_URL=<auto-injected by Render>
JWT_SECRET=<auto-generated by Render>
NULLIFIER_SECRET=<auto-generated by Render>
CONTRACT_ADDRESS=0x...        # from Sepolia deployment
RPC_URL=https://...           # Alchemy/Infura Sepolia
RELAYER_PRIVATE_KEY=0x...     # funded Sepolia wallet
RELAYER_ADDRESS=0x...         # matching address
FRONTEND_URL=https://...      # your Render frontend URL

# Recommended
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your@email.com
SMTP_PASS=your_app_password
SMTP_FROM=noreply@yourdomain.com

# Set to false in production (already set in render.yaml)
DEV_MODE=false
DEV_SHOW_OTP=false

# Optional — Twilio SMS for OTPs
TWILIO_ACCOUNT_SID=ACxxx
TWILIO_AUTH_TOKEN=xxx
TWILIO_PHONE_NUMBER=+1...
```
